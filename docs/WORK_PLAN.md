## 1. Главное

1. **База хорошая, её менять не нужно.** `main` — это апстрим `Riyozaki/RFAB_Online` v4.1.0 (`adf3573b`; файлы совпадают, потерялись только ссылки на сабмодули) плюс два твоих коммита. Апстрим с момента импорта не менялся, подтягивать нечего.
2. **Незаконченная работа неровная.** Первый коммит (`f65775a`, стабилизация) в основном верный, спорных изменений в нём три (M6, M8, M9). Второй (`6f7c753`, «глубокая адаптация RFAB») добавил механики, из которых три сломаны, а часть не подключена к игре (M4, M5). Самые опасные: бесплатный опыт при каждом переподключении (M1), сброс душ драконов в 1 (M2), лошадь, «запертая» за первым всадником (M3).
3. **Все тесты зелёные, и это ничего не говорит о перечисленных дефектах.** Тесты проверяют правило в изоляции, а не путь «клиент → сервер → клиент». Пример: тест спешивания шлёт пакет, который настоящий клиент послать не умеет.
4. **Клиент из этого репозитория сейчас нельзя собрать.** Пропали ссылки на четыре сабмодуля, CI выключен, версия не изменена. Свидетельств, что клиентская часть двух коммитов хоть раз компилировалась, нет.
5. **Адаптация под RFAB точечная.** Покрыты опыт, смерть, масштаб врагов, защита союзников, часть боссов, сейвы. Не затронуты уклонение, анимационные плагины сборки (OAR, Payload Interpreter), интерфейс сборки (TrueHUD, WheelMenu), ремесло, торговля, сон и быстрое путешествие.

Цель «как будто игра изначально онлайн» целиком в одну сессию не помещается. План ниже ставит вперёд то, без чего остальное бессмысленно (сборка, починка сломанного, диагностика), и отделяет то, что уйдёт в бэклог (раздел 8). Игру до конца работы проверить нельзя, поэтому результат работы — сборка, в которой проверено всё, что проверяется без игры, плюс инструменты, чтобы находки плейтеста чинить по логам.

## 3. Состояние кодовой базы

**Размер.** 2069 файлов. Клиент 64 тыс. строк, сервер 16 тыс., общий код (`common`) 16 тыс., протокол 14 тыс., тесты 17 тыс. В клиенте 107 точек входа из чужих потоков: 90 хуков движка, 2 функции Papyrus, 7 приёмников событий, 8 обработчиков интерфейса (данные `check_hook_discipline.py`).

**Что сделано хорошо и что нельзя ломать:**
- порт структур и адресов под SE 1.5.97 с автоматической сверкой;
- протокол и его фаззинг;
- единая модель владения NPC (`Authority::Lease`), ревизии здоровья, учёт ударов;
- жизненный цикл сессии, самовосстановление потерянного состояния, серверные выброшенные предметы;
- правило «поток движка только читает снимок и ставит задачу» с автоматической проверкой;
- серверные выключатели подсистем (`Session/Features.h`);
- быстрая петля на Linux: ядро и настоящий сервер без игры.

**Системные проблемы:**

## 4. Незаконченная работа: вердикт по каждому изменению

Брать апстрим «как основу» отдельно не нужно: импорт ему идентичен, а «взять апстрим» означало бы откатить оба коммита целиком и потерять верные исправления. Поэтому решение принимается по каждому изменению.

**Оставить** (после первой сборки в CI и плейтеста):

| Изменение | Почему верно |
|---|---|
| Индекс `kInfamy` 61 вместо 37 на сервере | 37 — это `VoicePoints`; сервер фильтровал не то значение |
| Защитные характеристики удалённых актёров через временный модификатор | раньше два канала по очереди писали в постоянный модификатор разные числа |
| Резерв серверной сущности 0 | `ServerId == 0` во многих местах означает «нет сущности» |
| `World::IsCreated()` в хуках сохранения | хуки могли обратиться к миру до его создания |
| Проверка типа материала лица перед записью текстуры, null-проверки в `FaceGenSystem` | запись указателя в чужое поле — порча памяти и вылет при выгрузке головы |
| Имена сейвов в UTF-8 и CP1251, проверка пары `.ess` + `.skse` | русские имена слотов не находились на диске |
| `secondaryAV` для `DualValueModifier`, привязка перк-множителя к своему эффекту | урон по здоровью вторым значением не опознавался |
| `GamePtr` в `ScopedCoopPartyTeammateFlags` | актёр мог быть удалён между установкой и снятием флага |
| Запрет сбивать союзников с ног, заклинания контроля по союзникам | закрывает дыру в «Единстве в битве» |
| Снимки для хуков через `shared_ptr`, обновление 10 раз в секунду | убирает глубокое копирование на каждый удар |
| `REQ_Combat_NoDeathHandling` сразу после загрузки | закрывает окно, когда Requiem мог перезагрузить сейв в одиночку |
| Правки `EncounterService` (подъём не сбрасывается вторым союзником, сброс боя при выходе последнего) | поведение покрыто стендом через настоящие пакеты |
| Хэш внешности удалённого игрока | убирает повторную пересборку лица при каждом спавне |

**Починить или выключить** (детали и места в коде — реестр, 9b):

| # | Изменение | Действие по умолчанию |
|---|---|---|
| M1 | Догон опыта опоздавшему | выключить по умолчанию; привязать к постоянному ключу игрока (`BuildPlayerIdentityKey`), считать «опыт сессии минус уже начисленное этому игроку» |

| M6 | Признак «враг» для масштабирования | класс цели назначает владелец один раз при появлении, он передаётся всем; эвристика в момент удара убирается |

## 6. План работ

### 6.1. Условие: плейтест один, в конце

Проверить игру можно будет только после завершения всей работы (решение владельца от 2026-11-14). До этого доступны два вида проверки:

| Проверка | Что подтверждает | Чего не подтверждает |
|---|---|---|
| 🧪 Петля на Linux (минуты) | логику сервера и общего кода, протокол, сценарии через настоящий сервер | всё, что делает движок игры |
| 🏗 Сборка в Windows CI (около 20 минут) | клиент компилируется и линкуется, собирается установщик | что клиент правильно работает в игре |

Третий уровень, 🎮 плейтест, наступает один раз, после этапа 8. Отсюда правила:

1. **Клиентский код, который работает с движком, не переписывается крупными кусками.** Проверить такое вслепую нечем. Правки в нём малые и локальные: решение выносится в `common/` и покрывается тестом, порядок вызовов движка не меняется.
2. **Каждое изменение поведения получает серверный выключатель** (механизм `Session/Features.h` и настройки `[Gameplay]` в `STServer.ini`). Если в плейтесте что-то сломается, оно отключается строкой в настройках сервера, без новой сборки. Исправления ошибок (проверки на null, время жизни объектов) выключателя не требуют.
3. **Использование функций движка сверяется с источниками:** CommonLibSSE, исходники SKSE (`src/skse64/` в `drake1ch/RFAB`), TiltedEvolution, скрипты RFAB. Ошибка M2 (значение вместо прибавки) ловится именно так.
4. **Каждый этап заканчивается сборкой из CI.** Это точки отката: если финальная сборка окажется хуже, по сборкам этапов видно, какой этап сломал.
5. **Всё, что может решить только игра, работу не блокирует.** Оно записывается в список проверки (`docs/PLAYTEST.md`) вместе с выключателем, которым отключается.
6. **Диагностика (этап 3) должна быть готова до финальной сборки**, чтобы один плейтест дал полную картину.

### 6.2. Общие правила

1. **Одна единица работы — один коммит.** Перед коммитом петля зелёная, строка реестра обновлена, запись в журнале (раздел 9) сделана. Состояние сессии живёт в репозитории, а не в памяти разговора.
2. **Тест стенда шлёт только то, что умеет слать клиент.** Появляется автоматическая проверка «контракт провода»: у каждого сообщения и вида события есть отправитель и получатель в боевом коде.
3. **Тесты проверяют поведение, а не текст исходников.**
4. **Любое изменение поведения меняет версию** и попадает в `CHANGELOG.md`.
